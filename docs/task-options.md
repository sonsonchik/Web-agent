# Описание передаваемых опций по заданиям

Документ фиксирует формат и смысл параметра `options`, который приходит вместе с заданием в API `wa_task`.

## 1. Общий контракт задания
Поля, приходящие от сервера:
- `task_code` — код задания.
- `options` — опции/параметры задания (строка).
- `session_id` — идентификатор сессии выполнения.
- `status` — статус (`RUN` или `WAIT`).

## 2. Формат поля options
Текущая реализация принимает `options` как строку без обязательного парсинга.

Рекомендованный формат для совместимости вперед:
- JSON-строка в UTF-8.
- Пример:
```json
{"source":"remote","path":"/files/data.csv","mode":"full"}
```

Если сервер передает не-JSON строку, агент не падает: значение передается в лог и файл результата как есть.

## 3. Поддерживаемые task_code

### `CONF`
Назначение: получить/подтвердить конфигурационные данные.

Текущее поведение агента:
- создает файл результата;
- пишет в него `task_code`, `options`, `session_id`, время выполнения;
- отправляет результат на сервер.

### `GET_FILE`
Назначение: получить файл (или инициировать шаг по работе с файлом).

Текущее поведение агента:
- создает файл результата;
- пишет в него `task_code`, `options`, `session_id`, время выполнения;
- отправляет результат на сервер.

## 4. Ошибки и коды результата
- `0` — успешно.
- `< 0` — ошибка выполнения.

Если `task_code` неизвестен, агент возвращает ошибку с сообщением:
`Неизвестный тип задания: <task_code>`.

## 5. Совместимость и расширение
Чтобы добавить новый тип задания:
1. Добавить обработку `task_code` в `src/main.cpp` (`executeTask`).
2. Задокументировать ожидаемый формат `options` в этом файле.
3. Добавить/обновить тесты под новый сценарий.
